# Changing the database schema

Background: `docs/adr/0002-core-data-model.md`. Tables live in
`apps/server/src/modules/<module>/schema.ts`, are re-exported from `src/db/schema.ts`, and
cross-module relations are in `src/db/relations.ts`. Migrations are SQL files in
`apps/server/drizzle/`, generated by drizzle-kit and committed.

## Steps

1. **Edit the schema** in the module's `schema.ts`. Follow the conventions: `id()` and
   `...timestamps` from `src/db/columns.ts`; camelCase names (SQL becomes snake_case);
   dates as `date({ mode: "string" })`; money as integer cents; enums built from an
   `as const` array in `packages/shared/src/domain.ts`; name every unique/check constraint
   and index (`<table>_<what>_key|idx`, `<table>_<rule>`).
2. **New table?** Re-export the module schema from `src/db/schema.ts`, add relations in
   `src/db/relations.ts`, and add a factory in `src/test/factories.ts` if tests need rows.
3. **New column on `persons`?** Add it to `PERSON_FIELD_TIERS` in
   `packages/shared/src/sensitivity.ts` (a test fails otherwise). Health data never goes
   on `persons`; it belongs to M13's tables.
4. **Generate**: `pnpm db:generate --name <short_snake_name>` (from the repo root; extra
   args pass through to drizzle-kit). If drizzle-kit asks whether a column was renamed or
   created, answer deliberately: a wrong "create" drops data.
5. **Read the SQL** in the new `apps/server/drizzle/NNNN_*.sql`. Watch for:
   - `DROP COLUMN` / `DROP TABLE` you did not intend;
   - `NOT NULL` added to an existing table without a default: needs a backfill. Split it:
     add nullable column → `UPDATE` backfill (hand-edit the SQL or add a second migration
     with `pnpm db:generate --custom --name backfill_x`) → set `NOT NULL`;
   - enum value removals or renames: Postgres cannot drop enum values; migrate the data to
     another value first, then recreate the type in a custom migration;
   - new unique constraints on tables that may already hold duplicates.
   Never edit a migration that is already on `main`; add a new one.
6. **Apply and test**: `pnpm db:migrate` (dev DB), then `pnpm check`. Tests recreate the
   `*_test` database from all migrations, so a broken migration fails there. Add service or
   constraint tests for new rules (use `withRollback`, `savepoint` and `pgCode` from
   `src/test/db.ts`).
7. **Seed**: update `src/db/seed.ts` if the new data is needed to develop screens; check
   with `pnpm db:seed --reset`.
8. **Commit** schema, migration (SQL plus `drizzle/meta/*`), and docs together. CI fails if
   the committed migrations do not match the schema (`db:check` + regenerate + diff).

## Troubleshooting

- *"Refusing to recreate …"*: `TEST_DATABASE_URL` must name a database ending in `_test`.
- *Database tests skipped*: no `DATABASE_URL`. Run `docker compose up -d` and copy
  `.env.example` to `.env` (cloud sessions start the local Postgres in the session hook).
- *Migration journal conflict after merging main*: delete your unmerged migration files and
  their `meta` snapshot/journal entries, merge, then run `pnpm db:generate` again.
